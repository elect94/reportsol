AI와 나만의 주식 리서치 도구 만들기 / 180분 제안(학습 160분+휴식 20분)
설치·실제 데이터·Google·에뮬레이터·예약 사전 검증. 응용 실습 포함. 13번 뒤와 23번 뒤에 휴식 10분씩.

01. 주식을 몰라도, 내 도구를 만듭니다. / 3분
애플·마이크로소프트로 배우는 검색·비교·저장·자동화.
기본값 | 두 회사 · 최근 한 달 · USD
결과 | 버튼으로 다시 쓰는 도구
방법 | 한 단계 요청 → 직접 확인
강사 메모: 발문: “두 상품의 정보를 매주 복사한다면 어떤 버튼이 필요할까요?” 종목 선택·투자 판단은 평가하지 않습니다. 앱·시트·문서·저장이 이어지는 모습을 먼저 보여줍니다.

02. 보고서 한 편과, 반복 도구의 차이. / 4분
한 번의 글이 목적이면 대화형 AI로도 충분할 수 있습니다.
한 번 | 자료를 주고 초안 받기
반복 | 다른 입력으로 같은 흐름 재사용
오늘 | 검색 · 저장 · 다시 읽기 연결
강사 메모: 1분 시연, 2분 짝 이야기, 1분 정리. “다음 주에는 무엇을 다시 해야 하나요?”라고 묻습니다. 특정 AI 도구만으로 가능한 기술이라고 설명하지 않습니다.

03. 필요한 용어는, 이것만 알면 됩니다. / 4분
AAPL·MSFT는 회사의 검색용 이름표입니다.
종목코드 | AAPL = 애플 · MSFT = 마이크로소프트
종가 | 그 거래일의 마감 가격
변화율 | 처음과 비교해 얼마나 달라졌나
강사 메모: 가상 100→110은 10% 증가입니다. 싼 주가가 좋은 회사라는 뜻은 아닙니다. 주말에는 거래 기록이 없을 수 있습니다. 이 수업은 투자 판단이 아니라 반복 작업 구현을 배웁니다.

04. 앱마다 맡은 일을, 하나씩 정합니다. / 4분
목록 → 조회·비교 → 문서 → 기록 → 점검.
Sheets → 앱 | 목록을 읽어 비교에 사용
Docs · Firebase | 문서 출력 · 기록 저장
규칙 · 스킬 · 예약 | 기준 · 순서 · 시점
강사 메모: Google 연결은 에이전트의 권한, 가격 조회·Firebase 저장은 웹앱 실행 경로입니다. 에이전트가 읽는다고 웹앱에 실시간 동기화가 생기지 않습니다. 교재 연결표를 봅니다.

05. 수업 폴더를 열고, 준비 표시를 확인. / 5분
설치·계정 연결은 사전 준비, 수업에서는 기능을 연결합니다.
폴더 | 강사 제공 시작 프로젝트
연결 | 실제 데이터 · Google · 연습 저장소
복구 | C1 비교 · C2 저장 단계 사본
강사 메모: 5분: 폴더1·class-setup2·첫 화면2. 준비 기록이 미확정이면 강사가 해결합니다. 현재 꾸러미에는 검증된 실시간 시작 앱이 없습니다. 강사 준비 요청문과 체크리스트로 수업 전 준비합니다.

06. 빈칸 대신, 완성 예시로 시작. / 5분
회사·기간·기능을 정해 두어 그대로 출발합니다.
검색 | 다른 회사면 다른 결과
비교 | 같은 첫날을 100으로 맞춤
저장 | 다시 열어도 같은 기록
강사 메모: P01 입력1·응답2·자기 말로 설명2분. 코딩·금융 용어를 외우지 않습니다. 회사는 바꾸지 않아도 되고, 초보자는 기본값을 유지합니다.

07. 규칙은, 매번 지킬 약속. / 5분
말투·단위·출처·확인 기준을 프로젝트에 저장합니다.
쉽게 | 회사 이름 먼저
정확히 | 날짜 · 단위 · 출처
작게 | 한 기능 수정 후 재확인
강사 메모: 메뉴1·X01실행2·예문확인2분. App은 프로젝트 Customizations→Rules→Workspace, IDE는 에이전트 패널 …→Customizations→Rules에서 시작하되 실제 버전을 확인합니다. 기존 규칙은 보존합니다.

08. 사람은 기준을, AI는 구현을 돕습니다. / 5분
입력·출력·완료 기준을 먼저 정합니다.
화면 | 검색어를 받는 창구
서버 · API | 요청 전달 · 자료 교환 약속
내 역할 | 기대한 결과인지 직접 조작
강사 메모: “알아서 잘”을 “AAPL을 검색하면 애플·NASDAQ 표시”로 고칩니다. JSON은 내부 자료 형식이라 학생이 작성할 필요 없습니다. 자동 생성된 코드도 실제 조작으로 확인합니다.

09. 작은 화면을, 먼저 눌러 봅니다. / 7분
검색·가격·비교가 놓일 자리를 만듭니다.
요청 | P02 한 개만 보내기
확인 | 입력창 · 버튼 · 미연결 표시
다음 | 화면 확인 후 연결
강사 메모: 시연1·생성4·조작2분. 대기 중 버튼 이름을 읽어 봅니다. 한 번에 모든 기능을 다시 요청하지 않습니다.

10. 검색창에, AAPL을 입력합니다. / 8분
AI 대화가 아닌 웹앱의 결과가 바뀌어야 합니다.
첫 입력 | AAPL 또는 애플
다음 입력 | MSFT 또는 마이크로소프트
실패 확인 | NO_SUCH_STOCK_123
강사 메모: P03실행5·세 검색3분. 제공처·키 설정은 강사 사전 준비입니다. 연결 실패를 가상 자료로 숨기지 않습니다.

11. 숫자 옆에, 날짜와 단위를. / 8분
가격을 외우지 않고 어디서 온 값인지 확인합니다.
기간 | 최근 한 달의 실제 거래일
단위 | USD · 달러
대조 | 첫 값 · 마지막 값 · 출처
강사 메모: P04실행5·원자료대조3분. 실제 가격을 교재에 고정하지 않은 이유는 조회 시점에 따라 달라지기 때문입니다. 계산만 가상100→110으로 설명합니다.

12. 두 회사가, 100에서 출발하게. / 7분
같은 기간의 변화 정도를 비교합니다.
선택 | 애플 + 마이크로소프트
계산 | 각 날짜 값 ÷ 첫 값 × 100
해석 | 110 = 출발점보다 10% 증가
강사 메모: P05실행4·첫날100확인1·중복선택·실패설명2분. 100은 달러가 아닙니다. 공통 거래일이 부족하면 비교 불가가 정직한 결과입니다.

13. 첫 완성 기준을, 내 손으로 확인. / 5분
AI의 “완료”와 실제 성공을 구분합니다.
조작 | AAPL → MSFT → 다시 AAPL
대조 | 이름 · 숫자 · 날짜 함께 변경
상태 | 성공 · 실패 · 미검증
강사 메모: 5분 짝 점검. 막히면 P08로 증상을 전달합니다. 다음 휴식10분에 강사 검증 C1 사본으로 따라잡습니다. 직접 만든 기능과 복구 사본 기능을 구분합니다.

14. 내 표가, 앱의 출발점. / 5분
Sheets 두 행을 읽고 비교 버튼으로 연결합니다.
준비 | 관심종목 탭 A1:E3
연결 | 에이전트가 내 시트 읽기
범위 | 읽은 시점의 목록
강사 메모: 5분: 준비 표를 열고 A1은 A열1행, A1:E3은 표전체라고 설명합니다. 원본 시트와 앱의 복사 시점을 나눠 표시합니다. handbook Google 준비절을 봅니다.

15. Sheets에서, 두 행 읽기. / 8분
본인 수업용 표를 실제로 읽습니다.
문서 | 리서치 연습 - 관심 목록
결과 | 회사명 · 코드 · 메모
확인 | 원본과 읽은 값 대조
강사 메모: 연결1·X02실행3·원본대조2·막힘대응2분. Remote Agents 앱 플러그인과 로컬 IDE 경로는 다릅니다. 검색 미지원이면 본인 시트 주소만 제공합니다.

16. 목록을 누르면, 비교에 넣기. / 7분
읽은 자료를 실제 사용 기능으로 바꿉니다.
구현 | 관심 목록 · 비교에 넣기
재사용 | 기존 가격 · 비교 기능
표시 | 시트를 읽은 시각
강사 메모: X03실행4·버튼2·원본수정후재읽기설명1분. 내부 파일은 AI가 처리하고 학생은 JSON을 만들지 않습니다.

17. 보고서 버튼으로, 현재 화면 정리. / 8분
같은 숫자를 다시 타이핑하지 않습니다.
구성 | 회사 · 기간 · 값 · 출처
검사 | 화면과 보고서가 같음
출력 | 인쇄 또는 PDF
강사 메모: P07실행5·버튼과대조3분. 뉴스는 필수가 아니며 미연결로 표시합니다. 현재 데이터를 양식에 배치하는 기능입니다.

18. 검토한 내용을, 내 Docs에 보관. / 7분
내용을 보고 본인 문서에 한 번 추가합니다.
미리 보기 | X04 대상 · 본문
저장 | 확인 후 X05 실행
재확인 | 문서 열어 값 대조
강사 메모: X04 2·직접확인1·X05 2·Docs열기2분. Docs 쓰기는 학생이 대상을 확인한 후 실행합니다. 공유·메시지 발송은 하지 않습니다.

19. 문서는 결과, 저장소는 다시 쓸 기록. / 5분
Firestore를 로컬 연습 환경에서 사용합니다.
Docs | 사람이 읽는 결과 문서
Firestore | 앱이 읽는 기록 보관함
에뮬레이터 | 운영 전 연습용 환경
강사 메모: 설명2·X06확인3분. Firebase MCP는 개발 도구 연결이며 앱 저장 연결을 대신하지 않습니다. 환경 설치는 사전 준비입니다.

20. 저장 버튼과, 기록 한 개 연결. / 10분
완료 표시 뒤에 실제 기록이 있어야 합니다.
내용 | 회사 · 기간 · 수치 · 출처
중복 | 같은 결과 = 같은 ID
확인 | 저장소에서 다시 읽기
강사 메모: X07구현5·직접저장2·중복확인3분. ID는 기록의 이름표입니다. 운영 클라우드로 자동 연결하지 않습니다.

21. 새로고침해도, 당시 기록 읽기. / 5분
화면에 남은 값과 저장한 값을 구분합니다.
다시 열기 | X08 목록 읽기
대조 | 전후 ID · 값
표시 | 저장 당시 기록
강사 메모: X08실행3·새로고침과대조2분. 이번 검증은 브라우저 새로고침입니다. 에뮬레이터 종료 후 보존은 내보내기·가져오기 등 별도 준비가 필요합니다.

22. 점검 순서를, 저장하고 예약. / 8분
규칙은 기준, 스킬은 순서, 예약은 실행 시점입니다.
절차 | X09 리서치 점검 저장
수동 | X10 먼저 한 번 실행
예약 | X11 2분 뒤 한 번
강사 메모: X09 3·X10 3·X11 2분. 교재의 세 카드를 순서대로 사용합니다. 수동 성공한 동일 대상만 예약합니다. 스킬 호출과 외부 쓰기 승인은 다른 문제입니다.

23. 한 가지 불편을, 내 말로 고치기. / 7분
완성된 기본 개선 문장이 준비되어 있습니다.
기본안 | 회사 이름 먼저
오류라면 | 조작 · 현재 · 기대 결과
확인 | 같은 버튼 다시 누르기
강사 메모: P09 또는 실제오류 P08 4·재검증3분. 예약이 실행되는 동안 개선합니다. 다음 휴식10분에도 해당 실행 환경은 유지합니다.

24. 동료가, 설명 없이 써보기. / 5분
막히는 지점을 하나 찾습니다.
2분 | 관심 목록 → 비교 → 저장
1분 | 멈춘 지점 말로 확인
2분 | 개선 기준 한 문장
강사 메모: 동료가 없으면 다른 순서로 자기 점검합니다. “좋아요” 대신 “애플 버튼을 바로 찾았다” 같은 관찰을 남깁니다.

25. 무엇이 됐는지, 근거로 확인. / 5분
검색·문서·저장을 같은 경로로 검사합니다.
기능 | 통과 · 실패 · 미검증
자료 | 실제 · 가상 예제 구분
연결 | 시점 복사 · 로컬 저장
강사 메모: P10으로 점검하고 직접 확인한 범위만 체크합니다. 강사 시연을 본 부분은 관찰로 적습니다.

26. 예약 등록과, 실제 실행은 다릅니다. / 4분
시간이 지났다고 성공이라고 하지 않습니다.
등록 | ID · 예정 시각
실행 | 실제 시각 · 점검 결과
종료 | 해당 대기 예약만 정리
강사 메모: X12로 실행 결과를 확인합니다. 예약은 실행됐으나 시트 읽기는 실패할 수 있습니다. 장기 Automations는 상시 실행·권한 등 별도 조건이 있습니다.

27. 내가 배운 것을, 네 문장으로. / 3분
불편 → 요청 → 변경 → 확인.
불편 | 매번 두 회사 자료 찾기
변경 | 목록 · 비교 · 저장 연결
확인 | 직접 본 결과 · 남은 한계
강사 메모: P11로 실제 활동을 정리합니다. 주식 전망 발표가 아닙니다. 직접 성공·도움받아 성공·관찰·미완료를 구분합니다.

28. 다른 일에도, 같은 구조를. / 3분
회사 대신 상품·강좌·행사를 넣어봅니다.
상품 | 목록 → 가격 비교 → 검토 문서
강좌 | 목록 → 일정 비교 → 신청 메모
전이 | 입력 · 출력 하나씩 바꾸기
강사 메모: 다른 업무 하나를 골라 입력과 출력을 말합니다. 공개·영구자동화·운영클라우드 전환은 기본 완료 조건이 아닙니다. P06뉴스·P12공개검토는 참고입니다.
