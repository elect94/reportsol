AI와 나만의 주식 리서치 도구 만들기 / 180분 제안(학습 160분+휴식 20분)
1~9페이지 보존. 이후 Sheets/P03 → Docs/P04 → Firebase/P05. Google·Firebase 실제 계정 예행연습 필요. 15번 뒤와 20번 뒤에 휴식 10분씩.

01. 주식을 몰라도, 내 도구를 만듭니다. / 3분
애플·마이크로소프트로 배우는 검색·비교·저장·자동화.
기본값 | 두 회사 · 최근 한 달 · USD
결과 | 버튼으로 다시 쓰는 도구
방법 | 한 단계 요청 → 직접 확인
강사 메모: 발문: “두 상품의 정보를 매주 복사한다면 어떤 버튼이 필요할까요?” 종목 선택·투자 판단은 평가하지 않습니다. 앱·시트·문서·저장이 이어지는 모습을 먼저 보여줍니다.

02. 보고서 한 편과, 반복 도구의 차이. / 4분
한 번의 글이 목적이면 대화형 AI로도 충분할 수 있습니다.
한 번 | 자료를 주고 초안 받기
반복 | 다른 입력으로 같은 흐름 재사용
오늘 | 검색 · 저장 · 다시 읽기 연결
강사 메모: 1분 시연, 2분 짝 이야기, 1분 정리. “다음 주에는 무엇을 다시 해야 하나요?”라고 묻습니다. 특정 AI 도구만으로 가능한 기술이라고 설명하지 않습니다.

03. 필요한 용어는, 이것만 알면 됩니다. / 4분
AAPL·MSFT는 회사의 검색용 이름표입니다.
종목코드 | AAPL = 애플 · MSFT = 마이크로소프트
종가 | 그 거래일의 마감 가격
변화율 | 처음과 비교해 얼마나 달라졌나
강사 메모: 가상 100→110은 10% 증가입니다. 싼 주가가 좋은 회사라는 뜻은 아닙니다. 주말에는 거래 기록이 없을 수 있습니다. 이 수업은 투자 판단이 아니라 반복 작업 구현을 배웁니다.

04. 기본값을 끝까지, 그대로 이어 씁니다. / 4분
검색 시험 후 기본 예제로 돌아와 같은 자료를 보고서·저장·점검에 씁니다.
시작 | 기본 예제로 시작
보관 | 지정 Docs · comparison_records
점검 | research-check · 2분 뒤 1회
강사 메모: 기본값이 회사 이름에만 머물지 않게 전체 흐름을 읽습니다. lesson-defaults.txt에 버튼·시트·문서·저장 묶음·점검표·예약을 정리했습니다. 실제 가격·URL·ID·성공 결과는 실행에서 확인합니다.

05. 수업 폴더를 열고, 준비 표시를 확인. / 5분
설치·계정 연결은 사전 준비, 수업에서는 기능을 연결합니다.
폴더 | 강사 제공 시작 프로젝트
연결 | 실제 데이터 · Google · 연습 저장소
복구 | C1 비교 · C2 저장 단계 사본
강사 메모: 5분: 폴더1·class-setup2·첫 화면2. 준비 기록이 미확정이면 강사가 해결합니다. 현재 꾸러미에는 검증된 실시간 시작 앱이 없습니다. 강사 준비 요청문과 체크리스트로 수업 전 준비합니다.

06. 빈칸 대신, 완성 예시로 시작. / 5분
회사·기간·기능을 정해 두어 그대로 출발합니다.
검색 | 다른 회사면 다른 결과
비교 | 같은 첫날을 100으로 맞춤
저장 | 다시 열어도 같은 기록
강사 메모: P01 입력1·응답2·자기 말로 설명2분. 코딩·금융 용어를 외우지 않습니다. 회사는 바꾸지 않아도 되고, 초보자는 기본값을 유지합니다.

07. 규칙은, 매번 지킬 약속. / 5분
말투·단위·출처·확인 기준을 프로젝트에 저장합니다.
쉽게 | 회사 이름 먼저
정확히 | 날짜 · 단위 · 출처
작게 | 한 기능 수정 후 재확인
강사 메모: 메뉴1·X01실행2·예문확인2분. App은 프로젝트 Customizations→Rules→Workspace, IDE는 에이전트 패널 …→Customizations→Rules에서 시작하되 실제 버전을 확인합니다. 기존 규칙은 보존합니다.

08. 사람은 기준을, AI는 구현을 돕습니다. / 5분
입력·출력·완료 기준을 먼저 정합니다.
화면 | 검색어를 받는 창구
서버 · API | 요청 전달 · 자료 교환 약속
내 역할 | 기대한 결과인지 직접 조작
강사 메모: “알아서 잘”을 “AAPL을 검색하면 애플·NASDAQ 표시”로 고칩니다. JSON은 내부 자료 형식이라 학생이 작성할 필요 없습니다. 자동 생성된 코드도 실제 조작으로 확인합니다.

09. 기본 예제 버튼을, 첫 화면에 둡니다. / 7분
두 회사와 최근 한 달을 미리 채웁니다.
기본 | 애플 AAPL · 마이크로소프트 MSFT
화면 | 기본 예제로 시작 버튼
연결 전 | 실제 조회 미연결 표시
강사 메모: 시연1·생성4·조작2분. 기본 선택이 AAPL·MSFT, 최근 한 달·USD인지 확인합니다. 이후 실습에서 학생이 종목을 다시 정하지 않습니다.

10. 지금은 HTML 완성, 아직 배포 전입니다. / 5분
P02까지는 파일 제작과 미리 보기입니다. 다음 단계에서 처음 배포합니다.
지금 | 내 HTML · 가상 데이터 · 미배포
3번 | Sheets 코드 준비 → 최초 배포 → 저장 확인
그다음 | 같은 배포에 Docs → Firebase 추가
강사 메모: 5분. 지금 보이는 화면은 HTML 미리 보기이며 학생 앱의 배포 주소는 아직 없습니다. 이 강의 사이트 주소도 학생 앱의 주소가 아닙니다. P03 코드 생성 후 13페이지에서 Google에 파일을 넣고 14페이지에서 처음 배포합니다. 그 주소에서 Sheets 저장을 확인한 뒤 P04로 갑니다.

11. 앱 연결은, 버튼이 일을 하게 하는 것. / 6분
이번에는 Google의 Apps Script를 연결 통로로 씁니다.
화면 | 지금 만든 HTML을 그대로 사용
연결 통로 | Apps Script가 Google에 저장
확인 | 실제 Sheets를 열어 두 행 대조
강사 메모: 6분. Antigravity는 코드를 수정하는 도구, Apps Script는 웹앱과 Google 작업의 실행 장소입니다. 에이전트 앱 플러그인 설치만으로 웹페이지 버튼이 연결되지는 않습니다. HTML을 나만 접근하는 웹앱으로 옮기는 이유를 설명합니다.

12. Sheets 연결 준비, 3번만 복사합니다. / 8분
아직 URL이 없어도 됩니다. 먼저 배포할 파일 두 개를 만듭니다.
입력 | 미배포 HTML
출력 | Index.html · Code.gs
다음 | 파일 옮기기 → 최초 배포
강사 메모: 8분. P03을 한 번 보냅니다. apps-script 폴더에서 출력 파일 두 개가 생겼는지 확인합니다. 코드가 생겨도 아직 배포 완료는 아닙니다. 13~14페이지의 최초 배포를 이어 진행합니다.

13. 파일 두 개를, Apps Script에 넣습니다. / 10분
코드를 이해해서 다시 쓰는 대신 생성한 파일을 정확히 옮깁니다.
새 프로젝트 | script.google.com → 새 프로젝트
파일 | Code.gs 교체 · HTML Index 추가
한 번 실행 | setupLesson → 본인 권한 확인
강사 메모: 10분. 프로젝트 이름은 두 회사 리서치 노트. Code.gs에는 서버 파일 전체, HTML 파일 Index에는 화면 전체를 붙입니다. setupLesson을 실행해 시트 ID를 저장하고 생성된 표를 확인합니다. 본인 스크립트인지 확인하며, 조직 차단은 강사에게 알립니다.

14. 여기서 처음 배포하고, Sheets 저장을 확인. / 8분
이 단계에서 학생 앱의 실행 주소가 처음 생깁니다.
최초 배포 | 새 배포 → 웹 앱 · 접근 나만
주소 받기 | 발급된 /exec URL 열기
연결 확인 | Sheets 저장 → 실제 표 열기
강사 메모: 8분. 내 배포 설정을 확인하고 직접 배포합니다. 받은 /exec 주소에서 기본 예제 시작 후 Sheets에 관심 목록 저장을 누릅니다. 로컬 HTML에서는 google.script.run이 없습니다. 나만 접근이 불가능한 환경은 공개로 넓히지 말고 강사에게 확인합니다.

15. 표에서 고친 메모가, 앱에도 보이나요? / 5분
저장 성공 문구보다 원본과 다시 읽은 값으로 확인합니다.
표 수정 | AAPL 메모를 메모 수정 확인으로
앱 조작 | 관심 목록 다시 읽기
중복 확인 | 두 번 저장해도 두 행
강사 메모: 5분. 수정 후 읽기부터 시험하고 나중에 저장을 누릅니다. 기본 두 회사는 유지합니다. 읽기 결과는 읽은 시점의 사본이며 자동 실시간 동기화가 아닙니다. 끝나면 휴식 10분.

16. 이제 Docs만, 하나 더 연결합니다. / 4분
Sheets에서 사용한 Apps Script 프로젝트를 그대로 씁니다.
입력 | 화면에서 작성한 보고서
처리 | 같은 연결 통로에 문서 기능 추가
결과 | 리서치 연습 - 비교 기록
강사 메모: 4분. 새 프로젝트나 새 OAuth 설정부터 시작하지 않습니다. 원래 보고서에는 110 USD 출처와 20거래일 문구가 남아 있습니다. 실제 배열은 각 8개 가상 관측치이며 현재 값과 맞추는 작업이 P04에 포함됩니다.

17. Docs 연결, 4번만 복사합니다. / 7분
현재 데이터로 고친 보고서를 같은 내용으로 저장합니다.
버튼 | 보고서 작성 → Docs에 보고서 저장
표시 | 가상 값 · 관측 기간 · 출처
중복 | 같은 보고서는 한 번만
강사 메모: 7분. P04를 한 번 보냅니다. 화면에서 보던 보고서와 Docs 본문이 다른 값을 갖지 않도록 하나의 보고서 자료를 함께 쓰게 합니다. 파일을 수동 JSON으로 만들지 않습니다.

18. 같은 배포에, 새 버전을 적용합니다. / 7분
파일을 저장하는 것과 배포 버전을 바꾸는 것은 다릅니다.
파일 교체 | 바뀐 Code.gs · Index 전체
배포 관리 | 기존 배포 편집 → 새 버전
주소 유지 | 같은 /exec 주소 새로고침
강사 메모: 7분. DocumentApp 권한이 추가되면 본인 계정에서 확인합니다. 변경된 Code.gs와 Index를 모두 저장하고 기존 배포를 새 버전으로 갱신합니다. 새 프로젝트를 만들지 않습니다. PDF가 필요하면 기존 인쇄 버튼을 씁니다.

19. 보고서와 문서를, 나란히 확인합니다. / 6분
실제 저장된 문서를 열어야 연결을 확인할 수 있습니다.
애플 | 237.50 USD · 교육용 가상
마이크로소프트 | 433.00 USD · 교육용 가상
기준 | 2026-11-06 · 표본 8개씩
강사 메모: 6분. 기본 예제 시작 → 보고서 작성 → Docs 저장 → 실제 문서 열기. 숫자는 업로드된 가상 데이터에서 나온 대조값이며 현재 주가가 아닙니다. 보고서 생성 시각과 관측 기준일을 구분합니다.

20. 한 번 더 눌러도, 같은 보고서 한 건. / 4분
중복·미작성·오류 상태도 기능의 일부입니다.
중복 | 저장 두 번 → 본문 한 건
미작성 | 시작 전 저장은 안내
오류 | 실패 시 완료 표시 없음
강사 메모: 4분. 보고서를 다시 만들지 않고 같은 보고서의 저장만 반복합니다. 새로 작성한 보고서는 별도 ID일 수 있습니다. 확인 후 휴식 10분.

21. 마지막은, 기록을 다시 꺼내기. / 4분
Firebase의 Firestore는 앱이 읽고 쓰는 기록 보관함입니다.
Sheets | 사람이 보는 표
Docs | 사람이 읽는 문서
Firestore | 앱이 다시 읽는 기록
강사 메모: 4분. 브라우저 임시 저장과 클라우드 저장을 구분합니다. 이번 목표는 같은 브라우저에서 다시 읽기입니다. 익명 로그인은 다른 기기까지 같은 사용자를 보장하지 않습니다.

22. 내 프로젝트와, 웹 앱을 등록합니다. / 7분
고유 프로젝트 ID는 Firebase가 만든 실제 값을 사용합니다.
프로젝트 | 표시 이름 리서치 연습
웹 앱 | 웹 아이콘 → research-note
설정 | firebaseConfig를 Antigravity에 전달
강사 메모: 7분. console.firebase.google.com에서 본인 연습 프로젝트를 생성합니다. Analytics와 Hosting은 이번 실습에 추가하지 않습니다. 표시 이름은 고정할 수 있지만 고유 ID는 학생마다 다릅니다. 웹 앱 설정만 복사하며 서비스 계정 비밀키를 받지 않습니다.

23. 로그인과 규칙을, 먼저 준비합니다. / 7분
본인 사용자 ID 아래의 기록만 읽고 쓰게 합니다.
Authentication | 로그인 방법 → 익명 사용
Firestore | Standard → 데이터베이스 생성
Rules | 교재의 본인 경로 규칙 적용
강사 메모: 7분. 프로덕션 모드로 시작하고 교재 규칙을 본인 연습 프로젝트에 적용합니다. 위치는 수업 기본 제안 asia-northeast3가 가능하면 선택하고 기존 DB 위치는 변경하지 않습니다. 테스트 모드 전체 공개로 해결하지 않습니다.

24. Firebase 연결, 5번만 복사합니다. / 8분
저장 버튼과 다시 읽기 버튼을 같은 앱에 붙입니다.
입력 | 콘솔에서 복사한 내 웹 앱 설정
저장 | 현재 보고서 ID · 수치 · 가상 표시
재조회 | 최근 5개 · 서버 응답 확인
강사 메모: 8분. P05를 보냅니다. 생성된 firestore.rules가 교재의 사용자별 경로와 같은지 확인합니다. 웹 SDK가 익명 인증 완료 후 접근해야 합니다. 앱 파일을 바꾸고 같은 Apps Script 배포에 새 버전을 적용합니다.

25. 새로고침하고, 기록을 다시 읽습니다. / 7분
앱·Firestore 콘솔·보고서에서 같은 기록인지 확인합니다.
저장 | 보고서 작성 → Firebase에 기록 저장
재조회 | 새로고침 → 최근 기록 다시 읽기
대조 | 같은 ID · 두 회사 값 · 가상 표시
강사 메모: 7분. UID가 새로고침 후 유지되는지 확인합니다. 콘솔에서 users → 현재 UID → comparison_records → 보고서 ID를 봅니다. 캐시에서만 읽었으면 서버 검증으로 체크하지 않습니다.

26. 막혔다면, 오류 하나씩 좁힙니다. / 5분
어느 단계가 실패했는지를 먼저 말합니다.
설정 | 프로젝트 ID와 앱 설정 확인
인증 | 익명 사용 여부 · UID 확인
권한 | UID · 경로 · 규칙 대조
강사 메모: 5분. Firebase 권한 문제를 Sheets 재배포나 전체 공개로 해결하지 않습니다. 오류 코드와 방금 누른 버튼을 AI에 전달합니다. 브라우저 저장 제한으로 UID가 유지되지 않으면 그 환경의 재조회는 미검증으로 남깁니다.

27. 완료 표시는, 직접 본 결과로. / 5분
세 연결을 각각 성공·실패·미검증으로 기록합니다.
Sheets | 두 행과 수정 메모
Docs | 같은 보고서 본문과 가상 표시
Firebase | 새로고침 뒤 같은 기록
강사 메모: 5분. 데이터 원본·저장 응답·다시 읽기를 나눠 확인합니다. 자료 제작 과정에서는 실제 계정 연결을 실행하지 않았습니다. 실습 결과는 각자의 조작 증거로 판단합니다.

28. 배운 것은, 내 버튼에 일 맡기기. / 5분
요구 → 연결 → 실행 → 원본 대조의 과정을 배웁니다.
요구 | 기존 버튼 하나에 역할 하나
구현 | AI가 만든 변경을 기존 앱에 적용
검증 | 외부 원본과 다시 읽은 값 비교
강사 메모: 5분. 프롬프트 2 이후에는 3→4→5만 진행했습니다. 주식 대신 도서 목록·수업 기록에도 같은 구조를 적용할 수 있다고 설명합니다. 새 확장 과제나 예약 설정을 추가하지 않습니다.
