커스터마이징 완성 예시 / 수업용 텍스트, 현재 환경에 설치한 결과가 아님
1. 프로젝트 규칙 예시
- 초보자가 읽는 화면은 쉬운 한국어로 쓰고 회사 이름을 종목코드보다 먼저 표시한다.
- 수치 옆에 단위·자료 기준 날짜·출처를 표시한다. 확인 못한 것은 확인 필요로 남긴다.
- 실제 조회·가상 예시·실패 상태를 구분한다.
- 기능 하나를 고친 뒤 같은 조작과 관련 기존 기능을 확인한다.
X01로 현재 환경의 Workspace Rules에 추가한다. 기존 파일을 통째로 바꾸지 않는다.

2. 스킬 본문 예시
아래는 프로젝트 스킬의 교육용 예시다. 설치된 제품의 탐색 경로를 확인한 뒤 X09로 추가한다.
파일 이름 예: research-check/SKILL.md
---
name: research-check
description: 두 회사 리서치 노트에서 리서치 점검을 요청하면 관심 시트와 앱 기록의 일치 여부를 읽기 전용으로 점검한다.
---
1. 확정된 내 ‘리서치 연습 - 관심 목록’의 관심종목!A1:E3을 읽는다.
2. 앱이 보유한 관심 목록과 시장·종목코드를 비교한다.
3. 최근 저장 기록의 회사·기간·출처·조회 시각을 확인한다.
4. 대상 | 확인 시각 | 결과 | 이유 표를 만든다.
5. 접근하지 못한 대상은 미확인으로 남긴다.
6. 이 점검은 자료·문서·공유 범위를 바꾸거나 메시지를 보내지 않는다.
스킬 호출 예: “리서치 점검 절차로 지금 한 번 확인해줘.”
실제 등록·실행 여부는 파일 경로와 수행 결과를 함께 확인한다. 이름을 말한 것만으로 실행 성공은 아니다.

3. 좋지 않은 규칙을 바꾸는 예
“주식 전문가처럼 완벽하게 분석해” → “가격의 기간·단위·출처를 보여주고 모르는 항목을 표시해.”
“다 자동으로 해” → “검증한 목록·기록을 한 번 읽고 결과를 이 대화에 남겨.”
“앱을 예쁘게” → “회사 이름과 비교에 넣기 버튼을 먼저 찾을 수 있게 해.”

4. 수정 예시 / 실제로 이런 증상을 관찰했을 때 사용
애플을 비교에 넣고 마이크로소프트를 눌렀는데 화면에 애플만 보여.
두 회사가 나란히 보여야 해. 같은 순서로 재현하고 필요한 부분만 고쳐줘.
이미 되는 검색과 저장은 유지하고 수정 후 같은 버튼 순서로 다시 확인해줘.
