2. Google Docs 연결 / 16–20페이지 · 28분 제안

완성할 것: 지금 앱에서 작성한 보고서를 본인 Google Docs에 저장하고 같은 내용인지 확인합니다.

왜 배우나: Sheets는 행과 열로 관리하는 표, Docs는 사람이 읽는 문서입니다. 같은 앱의 현재 자료를 다른 형식으로 보내는 방법을 배웁니다. Sheets에 연결했던 Apps Script에 DocumentApp 기능을 더하면 됩니다.

시작 전
P03의 코드 생성뿐 아니라 14페이지 최초 배포와 15페이지 Sheets 저장·다시 읽기를 마친 상태에서 시작합니다. 아직 URL이 없다면 먼저 14페이지를 진행합니다.
Sheets 연결에 사용한 동일한 Apps Script 프로젝트와 /exec URL을 엽니다. 새 프로젝트를 만들지 않습니다.
현재 보고서의 출처에 110 USD·2026-10-30이 남아 있고 표에는 20거래일이라는 고정 설명이 있습니다. 실제 sampleData는 회사별 8개 가상 값입니다. P04에서 이 불일치를 고치고 그 결과를 Docs로 보냅니다.

[04] Docs 연결
준비: P03에서 최초 배포와 Sheets 저장을 확인한 뒤 같은 파일·주소를 사용합니다.
이 단계 기본값: Docs: 리서치 연습 - 비교 기록 / 기존 보고서 버튼 사용

그대로 복사할 완성 예시
Sheets가 연결된 apps-script/Index.html과 Code.gs에 Google Docs 저장만 추가해 줘.
btn-create-report는 현재 sampleData로 수치·변화율·기간·출처를 계산해 미리 보기를 만들어 줘. 남아 있는 110 USD와 20거래일 고정 문구를 실제 배열의 값·기간·8개 관측치로 바로잡아 줘. ‘교육용 가상’과 ‘실제 시세 미연결’을 화면·보고서에 유지해 줘. 기본 예제 시작 전에는 작성을 막아 줘.
btn-export-docs는 ‘Docs에 보고서 저장’으로 연결해 줘. google.script.run과 DocumentApp으로 ‘리서치 연습 - 비교 기록’ 문서를 최초 한 번 만들고 ID를 보관해 줘. 대상·수치·관측 기간·가상 출처·미확인을 미리 보기와 같게 저장해 줘.
한 보고서에는 같은 ID를 유지하고 재클릭해도 중복 추가하지 마. 저장 중에는 버튼을 잠그고 완료 응답에서 실제 문서 링크를 보여 줘. 실패하면 성공 표시를 하지 마.
Sheets 기능은 유지해 줘. 바뀐 파일 전체와 권한 재확인·기존 배포의 새 버전 적용 순서를 알려 줘. 적용은 내가 직접 할게.

예상 결과: 앱의 보고서와 같은 내용이 본인 Google Docs에 저장됩니다.
직접 확인: 문서 링크를 열어 237.50 USD·433.00 USD·교육용 가상·2026-11-06을 대조하고 재클릭 시 중복이 없는지 봅니다.
막히면: 권한이 늘어난 경우 본인 스크립트의 요청 범위를 확인합니다. 배포 관리에서 새 버전을 적용했는지 확인합니다.

직접 따라 하기
1. P04 한 번 보내기
Antigravity에서 Sheets 기능을 붙인 같은 프로젝트에 프롬프트 04를 보냅니다. 현재 보고서의 값과 출처를 고친 뒤 Docs 저장 기능을 추가하도록 되어 있습니다.

2. 바뀐 파일 전체 옮기기
수정된 Code.gs와 Index.html 전체를 같은 Apps Script의 각 파일에 넣고 저장합니다. 함수 일부만 잘못 골라 붙이지 않도록 파일 이름을 대조합니다.

3. 기존 배포 갱신
배포 → 배포 관리 → 기존 배포의 편집 아이콘 → 버전 새 버전 → 배포를 누릅니다. Docs 권한이 추가되어 본인 계정 승인이 요청되면 스크립트와 범위를 확인합니다. 기존 /exec URL을 유지합니다.

4. 보고서 미리 보기
웹 앱을 새로고침하고 기본 예제로 시작 → 리서치 보고서 초안 생성 순서로 누릅니다. AAPL 237.50 USD, MSFT 433.00 USD, 관측 기간 2026-10-12~2026-11-06, 각 8개 가상 관측치인지 봅니다.

5. Docs에 저장
미리 보기를 확인한 뒤 Docs에 보고서 저장을 누릅니다. 저장 중 표시가 끝나고 실제 문서 링크가 나올 때까지 기다립니다. 문서 제목은 리서치 연습 - 비교 기록입니다.

6. 실제 문서 대조
링크를 눌러 본인 Docs를 엽니다. 두 회사·숫자·관측 기간·교육용 가상·실제 시세 미연결이 미리 보기와 같은지 확인합니다. 새 문서의 ID는 자동 보관해 다음 저장에서도 같은 문서를 씁니다.

7. 중복과 미작성 상태 검사
현재 보고서를 다시 생성하지 않고 Docs 저장만 한 번 더 누릅니다. 같은 보고서 ID가 두 번 추가되지 않아야 합니다. 페이지를 새로고침한 뒤 예제를 시작하지 않으면 보고서 작성·저장 대신 안내가 나와야 합니다.

성공 확인
Google Docs에서 실제 보고서 본문을 직접 열었습니다.
미리 보기와 Docs의 수치·기간·가상 표시가 같습니다.
같은 보고서 저장을 반복해도 중복 본문이 생기지 않습니다.

막혔을 때
DocumentApp 권한 부족 → 수정 코드를 저장했는지, 추가 권한을 본인 계정에서 확인했는지 봅니다. 실행 기록의 오류를 AI에게 전달합니다.
문서는 만들어졌는데 본문이 없음 → 버튼 클릭 시 보고서가 이미 생성되었는지 봅니다. 보고서 자료를 보내는 부분과 서버 응답을 함께 점검하게 합니다.
110 USD 또는 이전 날짜가 남음 → 현재 sampleData에서 값을 만들게 했는지 확인합니다. 기존 문자열을 재사용하지 않도록 해당 문장과 기대 결과를 AI에게 보여 줍니다.
저장 버튼이 계속 대기 상태 → 실패 처리에서도 버튼 잠금이 풀리도록 요청합니다. 서버 오류가 있는데 성공 문구를 띄우는 방식으로 고치지 않습니다.

노하우: 내용을 따로 두 번 만들면 서로 달라집니다. 화면 미리 보기·Docs·다음 Firebase에 같은 보고서 자료와 ID를 전달하도록 요청합니다. JSON 파일 제출은 필요 없습니다.
