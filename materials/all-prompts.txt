[01] 실습 폴더와 양식 준비
입력: research-workbench.html + stock-data-example.json + data-format.txt
준비된 research-workbench.html, stock-data-example.json, data-format.txt를 이번 실습 폴더에서 확인해줘.
목표는 Antigravity로 자료를 수집·검증해 JSON으로 저장하고, 웹페이지에서 종목을 검색해 보고서를 만드는 거야.
기존 파일을 보존하고 로그인 정보·비밀번호를 요구하지 마. 새 서버·유료 연결·외부 게시 없이 시작해줘.
양식 파일을 열고 JSON 불러오기 → DEMO 검색 → 종목 선택 → 보고서 작성 흐름을 설명해줘.

[02] 준비된 양식 먼저 사용하기
입력: research-workbench.html + stock-data-example.json
research-workbench.html을 열어 stock-data-example.json을 불러오는 방법을 안내해줘.
DEMO와 SAMPLE은 모두 교육용 가상 종목이야. 검색창에 DEMO 입력 → 결과 선택 → 보고서 작성 → 인쇄/PDF 저장 순서로 확인하자.
저장된 종목만 검색하며 웹페이지에서 인터넷 검색이나 AI 호출은 하지 않는다는 점을 설명해줘.
직접 확인하지 않은 동작은 검증했다고 하지 마. 파일을 임의로 변경하지 마.

[03] 관심 종목 자료 수집·데이터화
입력: 회사명 + 시장 + 기간 + 질문 + data-format.txt
관심 회사는 [회사명], 시장은 [시장], 기간은 [시작일~종료일], 질문은 [질문]이야.
data-format.txt와 stock-data-example.json의 구조를 읽고 공개 원자료에서 종목코드·종가·관련 뉴스 최대 3건을 찾아줘.
원문 주소·조회 시각·통화·시간대·가격 종류·수정주가 여부와 실제 기사 읽은 범위를 기록해줘.
가격·기사·인용문을 만들지 마. 제목만 확인한 기사는 본문 요약을 null로 남겨줘. 접근 실패·자료 누락은 missing에 기록해줘.
확인된 자료만 stock-data.json에 저장해줘. 기존 종목을 보존하고 symbol+market 기준으로 추가·갱신해줘. 날짜 중복·자료 혼합을 검사해줘.
수집이 막히면 이유를 알리고 제공된 가상 자료로 연습하되 실제 종목에 가상 수치를 넣지 마. 유료 연결·로그인 우회·외부 업로드는 하지 마.

[04] 수집이 어려우면 가상 자료로
입력: stock-data-example.json + data-format.txt + 제공 CSV/TXT
실제 자료 수집이 어려워서 제공된 가상 자료로 연습할게.
stock-data-example.json을 읽고 두 가상 종목 DEMO·SAMPLE의 구조를 설명해줘. 실제 기업 데이터로 바꾸지 마.
DEMO 가격은 stock-prices.csv, 뉴스는 news.csv와 news-01.txt·news-03.txt와 대조해줘. N02는 제목만 있고 본문은 미확인이야.
원본을 보존하고 stock-data.json에 연습용 사본을 준비해줘. 기존 파일이 있다면 기존 종목을 보존해 합쳐줘.
웹페이지에서 JSON 불러오기 → 두 종목 검색·선택 → 보고서 작성 순서로 안내해줘.

[05] JSON 가격 검증과 계산
입력: stock-data.json + data-format.txt
stock-data.json의 종목별 날짜순 정렬·중복 날짜·누락값·통화·시간대·가격 종류를 검사해줘.
자료가 없는 가격은 null로 유지하고 계산에서 제외해줘. 0이나 추정 가격으로 채우지 마.
유효 종가의 첫 값·마지막 값·변화액·변화율·최저·최고·산술평균을 직접 계산해줘.
변화율은 (마지막 / 첫 값 - 1) × 100이며 첫 값이 0이거나 유효 가격이 2개 미만이면 계산 불가야.
DEMO 전체 값은 100→110 USD, 변화율 10%, 평균 104.9 USD와 대조해줘. 실제 종목에는 해당 종목 통화를 써줘.
웹페이지 보고서와 수치를 비교하고 확인한 범위·오류를 알려줘.

[06] 기사 읽은 범위와 출처 점검
입력: stock-data.json + 기사 원문
stock-data.json의 뉴스별 날짜·제목·출처 주소·조회 시각·read_scope와 실제 원문을 대조해줘.
본문 확인 기사만 짧게 요약하고 제목만 읽은 기사는 summary:null로 유지해줘. 접근 불가 이유는 missing에 남겨줘.
계획을 완료 실적으로 바꾸지 마. 장문 원문을 복제하지 말고 직접 요약과 링크를 저장해줘.
가상 뉴스에는 교육용 가상 표시를 유지하고 실제 뉴스와 혼합하지 마. 수정한 항목과 근거를 보여줘.

[07] 사실·해석·미확인 저장
입력: stock-data.json + 원자료
종목별 analysis에 facts·interpretations·questions를 정리해줘.
facts와 interpretations는 text와 source_ids를 가진 항목으로 저장하고 출처 ID가 sources에 실제로 있는지 검사해줘.
가격과 뉴스의 시점이 겹친다는 이유만으로 인과관계를 단정하지 마. 미래 가격 예측·매매 권유는 넣지 마.
자료가 부족하면 빈 배열과 missing 설명을 유지해줘. 근거보다 강한 표현은 원문 → 수정문 → 이유로 설명해줘.
이 분석은 Antigravity에서 미리 저장하고 웹페이지 버튼은 저장된 분석을 양식에 배치한다는 점을 유지해줘.

[08] 두 번째 종목 추가·자료 갱신
입력: stock-data.json + 추가 회사·시장·기간
[추가 회사·시장·기간]의 공개 자료를 같은 양식으로 수집해 stock-data.json에 추가해줘.
기존 다른 종목은 보존하고 같은 symbol+market만 갱신해줘. 실제 종목 수집 실패 시 가상 수치로 대체하지 마.
수집 범위가 바뀌면 해당 종목의 analysis도 다시 확인하고 조회 시각·출처·missing을 갱신해줘.
JSON을 다시 불러온 뒤 종목명·코드 검색, 두 종목 전환, 없는 종목의 검색 결과 없음 표시를 확인해줘.
새 종목은 Antigravity에서 수집·저장한 뒤에야 웹페이지에서 검색된다는 안내를 유지해줘.

[09] 보고서 작성 버튼과 양식 개선
입력: research-workbench.html + stock-data.json + report-template.txt
준비된 research-workbench.html에 stock-data.json을 불러와 종목을 선택하고 보고서 작성 버튼을 확인해줘.
선택 종목의 전체 저장 기간·통화·출처·조회 시각을 사용하고 핵심 수치·차트·뉴스·사실·해석·미확인·출처를 배치해줘.
버튼은 저장 데이터로 양식을 구성하며 인터넷 검색·새 AI 분석은 하지 않아. 분석 변경은 Antigravity에서 JSON 수정 후 다시 불러와 반영해줘.
종목이나 파일을 바꾸면 이전 보고서를 숨기고 다시 작성하게 해줘. 자료 부족·형식 오류·검색 결과 없음도 표시해줘.
모바일과 인쇄/PDF 저장을 확인해줘. 필요한 양식 수정만 수행하고 외부 라이브러리·로그인·API 키·서버를 추가하지 마.

[10] 검색부터 보고서까지 최종 검사
입력: 완성 웹페이지 + stock-data.json + 원자료
JSON 불러오기 → 종목명·코드 검색 → 선택 → 보고서 작성 → 인쇄/PDF 저장을 실제로 확인해줘.
두 종목 전환 후 제목·수치·뉴스·출처가 함께 바뀌는지, 잘못된 JSON·없는 종목·누락 가격을 처리하는지 검사해줘.
가상/실제 구분·단위·날짜·계산식·기사 읽은 범위·사실과 해석·원문 링크를 원자료와 대조해줘.
360px 화면 넘침과 인쇄를 확인하고 새로 열었을 때 JSON을 다시 불러오는 사용법을 안내해줘.
실제 확인과 미검증을 구분하고 확인용 임시물만 정리해줘. 결과물과 원자료는 보존해줘.

[11] 선택 공유 준비
입력: 완성한 보고서 폴더
검색·보고서 웹페이지와 stock-data.json을 나중에 공유할 수 있도록 파일 목록을 정리해줘. 지금은 업로드하지 마.
공개할 research-workbench.html·공개 가능한 JSON·자료와 제외할 파일을 구분해줘.
수집 원문의 재배포 가능 범위와 개인정보를 확인하고, API 키, 비밀번호, 토큰, 개인정보, .env, 로그가 포함되지 않았는지 확인해줘.
하위 경로에서도 자료 링크가 열리는지 확인하고, 공개하면 코드와 데이터도 보일 수 있음을 알려줘.
최종 공개 대상 파일과 저장소 이름 제안을 보여주고 실제 게시 전에 내 확인을 기다려줘.

[12] 선택 GitHub Pages 게시
입력: 검토된 공개 파일 + 본인 계정
앞에서 검토한 공개 대상 파일만 내 GitHub 저장소 [저장소명]에 게시하려고 해.
먼저 연결된 계정과 저장소 이름, 공개 범위, 업로드 파일 목록을 보여줘. 내가 구체적으로 확인하기 전에는 업로드하지 마.
계정 인증은 본인이 공식 브라우저에서 진행하도록 안내하고 비밀번호·토큰·인증 코드를 대화에 요구하지 마.
확인 후에는 기존 파일과 이력을 보존하며 진행해줘. GitHub Pages가 실제로 열리는지 확인하고 저장소 주소와 실행 주소를 구분해서 알려줘.
게시된 화면에서 JSON 불러오기·종목 검색·보고서 작성·차트·기사 링크·모바일 표시를 확인해줘. 이 정적 보고서에는 실시간 AI 대화가 없음을 표시해줘.
