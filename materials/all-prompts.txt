[01] 만들 도구와 완료 기준
준비: 강사가 준비한 시작 프로젝트

그대로 복사할 완성 예시
주식을 처음 접하는 사람이 두 회사 자료를 비교하는 ‘두 회사 리서치 노트’를 만들 거야.
기본값은 애플 AAPL, 마이크로소프트 MSFT, 미국 NASDAQ, USD, 최근 한 달이야. 투자 추천은 하지 않아.
검색→가격→비교→관심 목록→보고서→기록 저장 흐름으로 만들자. 사용자에게 JSON 작성·업로드를 요구하지 마.
기존 파일과 class-setup.txt를 읽고 준비된 연결을 사용해줘. 검색·비교·저장의 완료 기준을 한 문장씩 적어줘.
지금은 요구사항을 정리하고 확인되지 않은 연결은 미확인으로 표시해줘.

예상 결과: 입력과 확인 방법이 있는 짧은 기준 세 개가 나옵니다.
직접 확인: “AAPL을 검색하면 애플이 나온다”처럼 직접 확인할 동작인지 봅니다.
막히면: 길면 “검색·비교·저장 각각 한 문장으로 줄여줘”라고 요청합니다.

[02] 먼저 작은 화면 만들기
준비: P01 완료 · 준비된 실행 환경

그대로 복사할 완성 예시
기존 시작 프로젝트에 검색창·검색 결과·가격 카드·두 회사 비교 영역을 만들어줘.
앱 이름은 ‘두 회사 리서치 노트’, 검색 예시는 ‘애플 또는 AAPL’, 기본 기간은 최근 한 달로 해줘.
미연결 영역에는 ‘실제 조회 미연결’을 표시하고 JSON 입력은 요구하지 마.
로딩·검색 결과 없음·오류를 구분하고 작은 화면과 키보드로도 조작하게 해줘.
기존 실행 규칙을 따라 열어서 버튼 동작을 확인하고 실행 주소를 알려줘.

예상 결과: 검색창과 아직 연결되지 않은 영역이 구분됩니다.
직접 확인: AAPL을 입력하고 버튼을 누릅니다. 화면만으로 실제 조회 성공이라 하지 않습니다.
막히면: “현재 시작 방법과 오류를 확인해서 이 프로젝트만 실행해줘”라고 요청합니다.

[03] 실제 종목 검색 연결
준비: 강사가 AAPL·MSFT 조회를 검증한 데이터 연결

그대로 복사할 완성 예시
class-setup.txt의 사전 검증된 제공처로 앱 검색창에 실제 종목 검색을 연결해줘.
애플·Apple·AAPL은 AAPL로, 마이크로소프트·Microsoft·MSFT는 MSFT로 찾게 해줘. 한글 별칭은 편의 기능이고 실제 회사·시장은 제공처로 확인해줘.
결과에 회사명·종목코드·시장을 보여주고 실패를 가상 값으로 채우지 마.
기존 서버를 사용하고 비밀 키를 화면 코드·로그에 넣지 마. 설정이 없으면 필요한 항목만 강사에게 알려줘.
AAPL, MSFT, NO_SUCH_STOCK_123 세 검색과 출처를 직접 확인해줘.

예상 결과: 두 실제 회사는 서로 다른 결과, 없는 종목은 결과 없음이 나옵니다.
직접 확인: 세 검색어를 웹앱에 직접 입력합니다. AI 대화만 바뀌면 미완료입니다.
막히면: 접근 오류는 강사에게 연결 확인을 요청하고 검증된 C1 사본으로 이어갑니다.

[04] 가격·날짜·출처 표시
준비: 실제 검색이 작동하는 상태

그대로 복사할 완성 예시
검색한 회사의 최근 한 달 일별 종가를 조회해 차트·첫 값·마지막 값·변화율을 보여줘.
종가는 ‘그 거래일의 마감 가격’이라고 설명하고 USD·거래일·조회 시각·출처·수정주가 여부를 표시해줘. 모르는 기준은 확인 필요로 남겨줘.
변화율은 (마지막 값/첫 값-1)×100이야. 유효 값 부족·첫 값 0이면 계산 불가로 표시해줘.
회사 변경 시 이전 가격을 지우고 늦게 도착한 이전 요청이 새 화면을 덮지 않게 해줘.
원자료 첫 값·마지막 값을 화면과 대조하고 실제 조회 실패를 그대로 보여줘.

예상 결과: 실제 날짜 범위와 USD가 가격 옆에 보입니다.
직접 확인: AAPL→MSFT로 바꾸어 이름·가격·날짜·출처가 같이 바뀌는지 봅니다.
막히면: 주말의 오늘 가격이 없다고 오류로 단정하지 않습니다. 마지막 거래일과 조회 날짜는 다릅니다.

[05] 같은 출발점으로 비교
준비: 두 회사의 가격 조회가 성공한 상태

그대로 복사할 완성 예시
AAPL과 MSFT를 선택해 최근 한 달의 공통 거래일로 비교하게 해줘.
공통 첫날을 각각 100으로 맞추고 각 날짜 값/공통 첫날 값×100으로 그려줘. 100은 달러가 아니라 같은 출발점이라고 설명해줘.
변화율·실제 기간·통화·가격 기준을 표시해줘. 공통 자료 부족·첫 값 0이면 비교 불가로 안내해줘.
한쪽 조회 실패와 같은 회사 중복 선택을 구분하고 선택을 바꿔도 검색·가격 기능을 유지해줘.
첫날 100과 마지막 값이 원자료 계산식에 맞는지 확인해줘.

예상 결과: 두 선이 같은 출발점 100에서 시작합니다.
직접 확인: 가격이 싼 회사가 좋은 회사라는 뜻이 아닙니다. 같은 기간의 변화만 봅니다.
막히면: 공통 날짜가 없다면 비교 불가 안내가 맞는 결과입니다. 날짜·가격을 지어내지 않습니다.

[06] 참고: 뉴스 연결
준비: 필수 경로를 끝낸 뒤 선택

그대로 복사할 완성 예시
선택한 회사의 뉴스 최대 3건을 제목·날짜·출처·원문 링크로 보여줘.
class-setup.txt에서 확인한 접근 가능한 출처를 사용하고 없으면 연결 조건부터 알려줘.
본문을 못 읽으면 ‘제목만 확인’이라고 표시하고 요약을 만들지 마. 조회 실패와 뉴스 없음을 구분해줘.
회사 변경 시 뉴스도 바뀌는지 확인해줘. 기사 전체 복제·가격 예측·투자 추천은 넣지 마.

예상 결과: 확보한 범위만 뉴스로 표시됩니다.
직접 확인: 원문 하나를 열어 제목·날짜·회사를 맞춥니다.
막히면: 미연결로 남겨도 기본 보고서는 만들 수 있습니다.

[07] 보고서 작성 버튼
준비: AAPL·MSFT 비교 화면 · 뉴스는 없어도 됨

그대로 복사할 완성 예시
현재 조회 결과로 ‘보고서 작성’ 버튼을 만들어줘. 제목은 ‘애플·마이크로소프트 비교 기록’이야.
기간, 첫 값·마지막 값·변화율, 단위·출처·조회 시각, 확인한 사실, 미확인 사항을 한 장으로 구성해줘.
뉴스 미연결이면 그대로 적어줘. 새 AI 분석이나 투자 추천은 생성하지 마.
같은 조회 결과에는 같은 기록 ID를 붙이고 인쇄/PDF 저장을 제공해줘. 회사·기간이 바뀌면 이전 보고서를 구분해줘.
화면과 보고서의 회사·수치·조회 시각이 같은지 확인해줘.

예상 결과: 현재 조회 결과가 정해진 양식으로 정리됩니다.
직접 확인: 마지막 값 하나와 조회 시각을 화면·보고서에서 맞춥니다.
막히면: 빈 자료면 “조회 전에는 버튼을 비활성화하고 이유를 보여줘”라고 요청합니다.

[08] 문제가 생겼을 때 수정
준비: 오류가 발생한 어느 단계에서나

그대로 복사할 완성 예시
방금 단계가 기대대로 동작하지 않아. 현재 화면과 최근 오류를 먼저 확인해줘.
내 조작을 확인하고 같은 순서로 재현해줘. 정보가 부족하면 마지막으로 누른 버튼과 현재 보이는 결과만 물어봐.
원인을 좁혀 필요한 부분만 고치고 이미 되는 검색·비교·저장은 유지해줘.
같은 조작으로 다시 확인한 결과를 알려줘. 못 한 검사는 미검증으로 남겨줘.

예상 결과: 문제의 원인과 수정 전후 결과가 설명됩니다.
직접 확인: 실제로 관찰했다면 “AAPL 선택→저장→새로고침했더니 목록이 비어요”를 덧붙입니다.
막히면: 오류가 없으면 사용하지 않습니다. 실패 경험을 만들 필요는 없습니다.

[09] 초보자를 위한 작은 개선
준비: 기본 예시 그대로 사용 가능

그대로 복사할 완성 예시
관심 목록과 비교 화면에서 종목코드보다 회사 이름을 먼저 보여줘.
‘애플 (AAPL)’, ‘마이크로소프트 (MSFT)’로 표시하고 ‘선택’ 버튼은 ‘비교에 넣기’로 바꿔줘.
검색·계산·저장은 유지해줘. 이미 이렇게 되어 있다면 같은 안내가 빠진 곳 하나만 맞춰줘.
수정 후 두 회사를 다시 골라 비교·저장이 유지되는지 확인해줘.

예상 결과: 코드를 외우지 않고 회사를 고를 수 있습니다.
직접 확인: 동료가 설명 없이 회사를 고르는지 봅니다.
막히면: 실제 불편이 다르면 그 한 문장만 바꿉니다.

[10] 사용자 관점의 최종 검사
준비: Google·저장·점검 활동까지 끝난 앱

AAPL·MSFT 검색→한 달 비교→시트에서 가져온 관심 목록→보고서→기록 저장→새로고침 후 다시 읽기를 직접 검사해줘.
없는 종목·한쪽 조회 실패·중복 저장·작은 화면도 확인해줘. Docs 문서와 앱의 수치·조회 시각을 대조해줘.
실제 연결·시트 읽은 시점의 목록·로컬 Firebase 연습 저장·미연결을 구분해줘.
예약 등록과 실제 실행은 따로 적고 기능마다 통과·실패·미검증 및 근거를 남겨줘.

예상 결과: 기능별 실제 확인 결과가 남습니다.
직접 확인: 직접 조작과 강사 화면 관찰을 구분합니다.
막히면: 미완료만 표시하고 성공한 작업을 보존합니다.

[11] 결과를 네 문장으로 설명
준비: 확인한 결과와 남은 한계

그대로 복사할 완성 예시
오늘 결과를 ‘불편→요청→변경→확인’ 네 문장으로 정리해줘.
기본 상황은 ‘두 회사 자료를 여러 창에서 매번 찾는 일이 번거롭다’야. 실제 구현·확인한 것만 써줘.
Sheets는 읽은 시점의 목록, Firebase는 로컬 연습 저장소, 예약은 실제 실행 여부를 표시해줘.
다시 실행하는 방법과 남은 준비를 적되 비밀 값은 제외해줘. 다른 활용 예로 상품 두 개 비교 도구를 한 문장 제안해줘.

예상 결과: 반복 작업을 어떻게 줄였는지 설명할 수 있습니다.
직접 확인: 보지 않은 성공·성과를 적지 않습니다.
막히면: 발표가 어려우면 누른 버튼과 달라진 화면을 보여줍니다.

[12] 참고: 공개 조건 검토
준비: 수업 후 선택 · 지금은 배포하지 않음

그대로 복사할 완성 예시
이 앱을 나중에 동료에게 공유하려고 해. 지금은 배포하지 말고 조건을 정리해줘.
화면 호스팅·검색 서버·개인 Google 자료 권한·Firebase 운영 저장 권한을 나누어 확인해줘.
로컬 에뮬레이터를 인터넷 공개 저장소로 쓰지 마. Hosting만으로 서버·시세·로그인이 생긴다고 가정하지 마.
공개 대상·자료·계정·비용과 미확인 항목을 보여줘. 실제 게시·클라우드 전환은 별도로 검토할 거야.

예상 결과: 공유에 필요한 조건을 확인합니다.
직접 확인: 공개 주소가 없으면 미배포입니다.
막히면: 개인 연습 환경까지가 이번 수업입니다.
