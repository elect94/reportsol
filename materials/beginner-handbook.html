1. Google Sheets 연결

지금 앱의 버튼으로 본인 Google 표에 두 회사를 저장하고, 표에서 고친 메모를 다시 읽습니다.

왜 배우나요?

HTML은 화면을 보여 주지만 Google 표를 변경할 권한은 갖고 있지 않습니다. Apps Script는 Google 계정 권한으로 표를 처리하는 연결 통로입니다. 이번에는 현재 HTML을 그 통로 안에서 실행해 별도 서버와 로그인 화면을 만드는 일을 줄입니다.

시작 전

  • P02까지는 HTML을 만들고 미리 보기한 미배포 상태입니다. 배포 URL은 준비물이 아닙니다. Antigravity 미리 보기나 이 강의 사이트의 주소를 학생 앱의 배포 주소로 쓰지 않습니다.
  • 지금까지 만든 HTML을 Antigravity에서 열어 둡니다. 수업 원본이 필요하면 research-note-start.html을 프로젝트에 넣습니다. 두 파일이 있으면 실제로 수정할 현재 파일 하나를 지정합니다.
  • 기본 예제로 시작을 눌러 애플 237.50 USD, 마이크로소프트 433.00 USD가 교육용 가상 값으로 표시되는지 봅니다. 이 값은 연결 확인용이며 시세 API를 새로 준비하지 않습니다.
  • 본인 Google 계정으로 script.google.com에 로그인합니다. Apps Script 사용이 조직에서 차단되는지 강사가 수업 전에 확인합니다.

프롬프트 03

Sheets 연결과 최초 배포

미배포 상태의 P02 HTML만 준비합니다. 배포 주소는 아직 없습니다.

Sheets: 리서치 연습 - 관심 목록 / 관심종목 / AAPL·MSFT

프롬프트 2까지 만든 HTML은 아직 미배포 상태야. 배포 주소를 요구하지 말고 Sheets 연결 코드와 최초 배포를 준비해 줘.
원본을 보존하고 apps-script/Index.html과 Code.gs를 만들어 줘. Apps Script 웹앱에서 google.script.run으로 호출하고 doGet은 Index를 열어 줘.
setupLesson은 ‘리서치 연습 - 관심 목록’ 시트를 최초 한 번 생성해 ID를 보관해 줘. 관심종목 탭의 열은 회사명·종목코드·시장·메모·사용. 기본 행은 애플/AAPL/NASDAQ/아이폰 회사/예, 마이크로소프트/MSFT/NASDAQ/윈도 회사/예야.
기존 btn-export-sheets를 ‘Sheets에 관심 목록 저장’으로 연결해 줘. 같은 종목은 중복 없이 갱신하고 성공 응답에만 표 링크를 보여 줘. 표를 다시 읽는 버튼도 추가해 줘.
기존 비교·보고서와 가상 표시는 유지해 줘. 배포 전 로컬 미리 보기에서는 외부 연결 대기를 표시해 줘. 파일 2개 복사 → setupLesson 실행 → 나만 접근하는 웹앱 최초 배포 → 발급된 주소에서 Sheets 저장 확인 순서로 안내해 줘. 배포는 내가 직접 할게. 코드 생성만으로 배포나 연결 성공이라고 하지 마.

예상 결과: 코드 준비 후 직접 최초 배포하고, 발급된 주소에서 Sheets 저장을 확인합니다.

직접 확인: 시트의 AAPL 메모를 아이폰 회사 → 메모 수정 확인으로 바꾸고 앱에서 다시 읽습니다. 두 번 저장해도 두 행인지 봅니다.

막히면: google.script.run 오류면 로컬 파일이 아니라 Apps Script의 배포 URL인지 먼저 확인합니다.

직접 따라 하기

  1. P03으로 연결 코드 준비

    아래 완성 프롬프트 03을 Antigravity에 보냅니다. apps-script/Index.html과 Code.gs가 생기면 파일을 각각 열어 봅니다. 아직 배포된 것은 아닙니다. 원본을 보존하고 아래 파일 옮기기와 최초 배포를 이어 진행합니다.

  2. Google에 새 프로젝트 만들기

    Apps Script에서 새 프로젝트를 누릅니다. 왼쪽 위 제목을 두 회사 리서치 노트로 바꿉니다. Sheets·Docs에서 이 프로젝트 하나를 계속 씁니다.

  3. Code.gs 옮기기

    편집기의 Code.gs 내용을 선택하고, AI가 만든 Code.gs 전체로 바꿉니다. 코드 블록의 백틱은 붙이지 않습니다. 이 파일은 표를 만들고 읽고 저장하는 역할입니다.

  4. 화면 파일 옮기기

    파일 옆 + → HTML을 선택하고 이름을 Index로 입력합니다. 만들어진 Index.html 내용을 AI가 만든 Index.html 전체로 바꿉니다. 기본 HTML 골격을 남기고 그 안에 또 전체 HTML을 넣지 않습니다.

  5. 저장하고 최초 설정 실행

    저장 아이콘 또는 Ctrl/Cmd+S를 누릅니다. 함수 선택 목록에서 setupLesson을 골라 실행합니다. 본인 계정·스크립트 이름·요청 권한을 확인합니다. 조직 정책으로 차단되면 우회하지 않고 강사에게 알립니다.

  6. 만들어진 표 확인

    setupLesson이 만든 시트 링크를 열거나 내 Drive에서 리서치 연습 - 관심 목록을 찾습니다. 관심종목 탭에 머리글과 기본 두 행이 있어야 합니다. 같은 이름의 기존 문서를 임의로 선택하지 않고 이번에 생성해 보관한 ID를 사용합니다. 편집기에서 표를 만든 것은 웹앱 배포와는 별개입니다.

  7. 웹 앱 최초 배포 / 14페이지

    여기서 학생 앱을 처음 배포합니다. 오른쪽 위 배포 → 새 배포 → 유형 선택의 웹 앱을 고릅니다. 실행 사용자는 나, 접근할 수 있는 사용자는 나만으로 설정하고 내용을 확인한 뒤 직접 배포합니다. 나만 항목이 없는 환경은 강사에게 확인하며 누구나로 넓히지 않습니다.

  8. 배포 주소에서 실행

    배포 결과의 /exec로 끝나는 웹 앱 URL을 엽니다. 로컬 파일 더블클릭 화면과 구분합니다. 기본 예제로 시작 → Sheets에 관심 목록 저장을 누르고, 성공 뒤 표시된 실제 표 링크를 엽니다.

  9. 다시 읽기 확인

    시트 AAPL 행의 메모를 메모 수정 확인으로 바꿉니다. 먼저 앱의 관심 목록 다시 읽기를 누르고 변경된 메모가 보이는지 봅니다. 그 다음 두 번 저장해도 AAPL·MSFT가 중복되지 않는지 확인합니다.

직접 성공 확인

  • 시트에 머리글 1행과 회사 2행이 있습니다.
  • 표의 메모를 수정한 뒤 다시 읽은 앱 값이 같습니다.
  • 저장 중·실패·완료가 구분되고, 완료일 때 실제 시트 링크가 열립니다.

2. Google Docs 연결

지금 앱에서 작성한 보고서를 본인 Google Docs에 저장하고 같은 내용인지 확인합니다.

왜 배우나요?

Sheets는 행과 열로 관리하는 표, Docs는 사람이 읽는 문서입니다. 같은 앱의 현재 자료를 다른 형식으로 보내는 방법을 배웁니다. Sheets에 연결했던 Apps Script에 DocumentApp 기능을 더하면 됩니다.

  • 현재 보고서의 출처에 110 USD·2026-10-30이 남아 있고 표에는 20거래일이라는 고정 설명이 있습니다. 실제 sampleData는 회사별 8개 가상 값입니다. P04에서 이 불일치를 고치고 그 결과를 Docs로 보냅니다.

프롬프트 04

Docs 연결

P03에서 최초 배포와 Sheets 저장을 확인한 뒤 같은 파일·주소를 사용합니다.

Docs: 리서치 연습 - 비교 기록 / 기존 보고서 버튼 사용

Sheets가 연결된 apps-script/Index.html과 Code.gs에 Google Docs 저장만 추가해 줘.
btn-create-report는 현재 sampleData로 수치·변화율·기간·출처를 계산해 미리 보기를 만들어 줘. 남아 있는 110 USD와 20거래일 고정 문구를 실제 배열의 값·기간·8개 관측치로 바로잡아 줘. ‘교육용 가상’과 ‘실제 시세 미연결’을 화면·보고서에 유지해 줘. 기본 예제 시작 전에는 작성을 막아 줘.
btn-export-docs는 ‘Docs에 보고서 저장’으로 연결해 줘. google.script.run과 DocumentApp으로 ‘리서치 연습 - 비교 기록’ 문서를 최초 한 번 만들고 ID를 보관해 줘. 대상·수치·관측 기간·가상 출처·미확인을 미리 보기와 같게 저장해 줘.
한 보고서에는 같은 ID를 유지하고 재클릭해도 중복 추가하지 마. 저장 중에는 버튼을 잠그고 완료 응답에서 실제 문서 링크를 보여 줘. 실패하면 성공 표시를 하지 마.
Sheets 기능은 유지해 줘. 바뀐 파일 전체와 권한 재확인·기존 배포의 새 버전 적용 순서를 알려 줘. 적용은 내가 직접 할게.

예상 결과: 앱의 보고서와 같은 내용이 본인 Google Docs에 저장됩니다.

3. Firebase 연결

현재 보고서를 Firestore에 저장하고 같은 브라우저에서 새로고침한 뒤 다시 읽습니다.

왜 배우나요?

Firestore는 앱이 다시 읽을 수 있는 클라우드 기록 보관함입니다. Firebase 프로젝트 등록, 인증, 저장 권한은 서로 다른 설정입니다. 이번에는 로그인 화면을 늘리지 않고 익명 로그인으로 각 브라우저 사용자를 구분합니다.

시작 전

  • Sheets·Docs가 동작하는 앱을 유지합니다. 본인 Google 계정으로 console.firebase.google.com에 로그인합니다.
  • 프로젝트를 만들 수 있는 계정인지 강사가 수업 전에 확인합니다. 이번 실습에 결제 연결·Hosting·Functions·장기 자동화는 요구하지 않습니다. 요금제·사용량 조건은 본인 콘솔에서 확인합니다.
  • 같은 일반 브라우저에서 실습합니다. 익명 계정은 다른 브라우저·기기 또는 사이트 데이터 삭제 후 같은 사람임을 복구하는 기능이 아닙니다.

Firestore Rules에 붙일 수업 규칙

본인 새 연습 프로젝트에서만 적용합니다. users 아래의 같은 UID 기록만 허용합니다.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/comparison_records/{reportId} {
      allow read, write: if request.auth != null
                        && request.auth.uid == userId;
    }
  }
}
