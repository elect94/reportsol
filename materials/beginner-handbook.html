한 단계씩 따라 하기

  1. 강사가 전달한 시작 프로젝트를 새 수업 폴더로 엽니다. 현재 폴더 이름이 ‘두 회사 리서치 노트’ 실습용인지 확인합니다. 기존 개인 프로젝트에 전체 요청문을 보내지 않습니다.
  2. class-setup.txt를 엽니다. 데이터 제공처·AAPL/MSFT 확인 결과·실행 방법·Google 연결 방식·로컬 저장소 상태가 확인됨이어야 합니다. 현재 자료에는 빈 준비 항목을 ‘확인 필요’로 표시했습니다. 강사가 채웁니다.
  3. 본인 Google Sheets에서 빈 스프레드시트를 만들고 제목을 ‘리서치 연습 - 관심 목록’으로, 아래쪽 탭 이름을 ‘관심종목’으로 바꿉니다. A1 셀을 누르고 아래 ‘관심 목록 표 복사’ 버튼으로 복사한 표를 붙입니다. A1:E3에 제목 행과 회사 두 행이 들어갔는지 봅니다.
  4. 본인 Google Docs에서 빈 문서를 만들고 제목만 ‘리서치 연습 - 비교 기록’으로 정합니다. 본문은 비워 둡니다. 공유 범위를 넓히지 않아도 됩니다. 생성이 어려우면 강사가 준비한 본인용 사본으로 참여합니다.
  5. Antigravity 연결은 수업에서 정한 경로 하나만 사용합니다. Remote Agents에서는 Customizations→Marketplace에서 Google 앱 연결을 확인하는 경로가 공식 안내에 있습니다. 로컬 IDE에 같은 메뉴가 있다고 가정하지 않습니다. 강사가 검증한 도구 목록에서 Sheets 읽기·Docs 읽기/쓰기를 확인합니다.

  7. 강사가 제공한 앱 주소를 엽니다. 원격 수업 환경은 그 환경의 HTTPS 주소를 사용합니다. 로컬 개발 환경과 원격 서버를 혼동해 브라우저 주소를 임의로 바꾸지 않습니다.

3. 검색→가격→비교를 작게 만들기

강사가 이렇게 설명합니다

  2. P03을 보냅니다. 제공처와 권한은 class-setup에 강사가 적은 것을 사용합니다. 초보자가 수업 중 데이터 서비스를 새로 고르지 않습니다.
  3. 웹앱에 AAPL을 넣고 검색합니다. 애플·AAPL·NASDAQ을 확인합니다. MSFT로 바꿔 마이크로소프트가 나오는지 봅니다. NO_SUCH_STOCK_123은 결과 없음이어야 합니다.
  4. P04를 보냅니다. 기본 기간은 최근 한 달입니다. 출처의 첫 값·마지막 값 중 한 개를 직접 열어 화면 수치와 맞춥니다. 자료가 지연돼도 지연 표시가 정확하면 실시간이라고 과장하지 않습니다.
  5. 회사를 빠르게 바꿔 이름만 바뀌고 가격이 남지 않는지 봅니다. 문제가 보이면 지금 단계에 P08을 사용합니다. 오류가 없으면 임의로 만들지 않습니다.

  7. 비교 화면을 강사에게 보여줍니다. 제한 시간을 넘기면 검증된 C1 사본으로 이어가고 자신이 만든 부분과 도움받은 부분을 기록합니다. 응용 실습 시간을 전부 없애지 않습니다.

6. Firebase에 비교 기록 저장·다시 읽기

먼저 이해하기

Firestore는 기록 보관함입니다. 에뮬레이터는 로컬 연습 환경입니다. Firebase MCP는 AI의 개발 도구 연결이며, 실제 앱 저장은 별도로 구현해야 합니다.

강사가 이렇게 설명합니다

“Docs는 사람이 읽는 문서, Firestore는 앱이 다시 읽는 기록입니다. 둘 다 저장이지만 다시 사용하는 방식이 다릅니다.”

한 단계씩 따라 하기
