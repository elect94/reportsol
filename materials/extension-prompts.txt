[X01] 프로젝트 규칙 적용
준비: Workspace Rules 또는 확인된 프로젝트 규칙 위치

그대로 복사할 완성 예시
현재 프로젝트에만 ‘초보 리서치 도구’ 규칙을 추가해줘. 기존 규칙은 보존해줘.
①쉬운 한국어·회사명 우선 ②수치에 단위·기준 날짜·출처 ③실제 자료·가상 시연·실패 구분 ④기능 하나 수정 후 같은 조작으로 확인.
현재 버전이 읽는 위치에 저장하고 적용 경로를 알려줘. 전역 설정은 바꾸지 마.
가격 카드 설명 예시 한 문장으로 적용을 보여줘. 예시 숫자는 가상 예시라고 표시해줘.

예상 결과: 프로젝트 규칙과 기준을 지킨 예시 문장이 보입니다.
직접 확인: 다음 가격 화면에서도 기준이 유지되는지 봅니다.
막히면: 메뉴가 다르면 제품 형태를 확인합니다. 기존 AGENTS.md를 덮어쓰지 않습니다.

[X02] Sheets 두 행 읽기
준비: 내 수업용 ‘리서치 연습 - 관심 목록’ 문서

그대로 복사할 완성 예시
연결된 Google Sheets에서 내 ‘리서치 연습 - 관심 목록’ 문서를 찾아줘.
동명이 여러 개면 제목·링크를 보여주고 내가 고르게 해줘. 확정 문서의 ‘관심종목’ 탭 A1:E3만 읽어줘.
열은 회사명·종목코드·시장·메모·사용, 행은 애플/AAPL/NASDAQ/아이폰 회사/예, 마이크로소프트/MSFT/NASDAQ/윈도 회사/예야.
원본을 수정하지 말고 실제 읽은 값·링크·시각을 보여줘. 미연결이면 읽었다고 하지 마.

예상 결과: 시트의 두 행과 읽은 시각이 보입니다.
직접 확인: A2·B2·B3를 원본과 맞춥니다. 기본 예시를 복창한 것만으로 통과하지 않습니다.
막히면: 파일 검색 미지원이면 본인 시트를 열어 주소 한 개를 붙입니다.

[X03] 관심 목록을 앱에 연결
준비: X02에서 실제 읽은 두 행

그대로 복사할 완성 예시
방금 실제 읽은 시트에서 ‘사용=예’인 두 행을 앱 관심 목록에 반영해줘. 시장+종목코드로 중복을 막아줘.
회사마다 ‘비교에 넣기’ 버튼을 만들고 기존 실제 가격 조회에 연결해줘.
목록 출처·읽은 시각과 ‘시트 읽은 시점의 목록’ 표시를 넣어줘. JSON은 내부 처리하고 사용자 입력을 요구하지 마.
에이전트의 시트 읽기를 웹앱 실시간 동기화라고 표시하지 마.
두 버튼으로 같은 비교 기능을 사용할 수 있는지 확인해줘.

예상 결과: 두 회사가 앱 관심 목록에 표시됩니다.
직접 확인: 버튼→실제 가격·비교까지 이어지는지 봅니다.
막히면: 원본 수정 후 갱신은 X02→X03 재실행입니다. 앱 새로고침만으로 시트를 다시 읽지 않습니다.

[X04] Docs 초안 미리 보기
준비: P07 보고서 · 내 빈 ‘리서치 연습 - 비교 기록’ 문서

그대로 복사할 완성 예시
현재 앱 보고서로 내 Google Docs ‘리서치 연습 - 비교 기록’에 추가할 내용을 미리 보여줘.
제목·두 회사·실제 기간·수치·단위·출처·조회 시각·미확인 사항·기록 ID 순서로 정리해줘. 값을 추측하지 마.
동명 문서가 여러 개면 링크로 대상을 먼저 고르게 해줘.
지금은 확정 대상 링크와 추가될 본문을 보여주고 앱 보고서와 값이 같은지 대조해줘.

예상 결과: 어디에 무엇이 저장될지 보입니다.
직접 확인: 마지막 값·조회 시각을 화면과 비교합니다.
막히면: 앱 화면 접근이 없으면 프로젝트의 해당 보고서 출력 파일을 읽게 합니다. 숫자를 다시 만들지 않습니다.

[X05] 검토한 Docs에 추가
준비: X04의 실제 대상·초안을 직접 확인한 뒤 실행

그대로 복사할 완성 예시
방금 확인한 내 ‘리서치 연습 - 비교 기록’ 문서와 초안을 승인해. 그 문서 끝에 초안을 한 번 추가해줘.
기존 내용은 보존하고 같은 기록 ID가 있으면 중복 추가하지 마. 공유 범위 변경·메시지 발송은 하지 마.
같은 문서를 다시 읽어 회사·기록 ID·조회 시각을 확인하고 문서 링크를 알려줘.

예상 결과: 본인 문서 끝에 검토한 내용이 한 번 추가됩니다.
직접 확인: 직접 문서를 열어 봅니다. Docs는 편집, Drive는 파일 보관을 맡습니다.
막히면: 권한이 없으면 PDF로 보관하되 Docs 성공으로 표시하지 않습니다.

[X06] Firebase 연습 연결 확인
준비: 강사가 준비한 로컬 Firestore 에뮬레이터

그대로 복사할 완성 예시
class-setup.txt의 로컬 Firestore 연습 환경을 확인해줘. demo-로 시작하는 연습 프로젝트만 써줘.
앱 서버에서 접근 가능한 에뮬레이터 주소·프로젝트 ID 일치·실행 상태를 확인하고 비밀 값은 출력하지 마.
브라우저→기존 앱 서버→로컬 에뮬레이터 흐름을 사용해줘. 원격 수업에서 학생 브라우저의 localhost로 연결하지 마.
운영 클라우드로 자동 전환하거나 프로젝트·결제·배포를 만들지 마. 준비되지 않았다면 강사에게 필요한 항목을 알려줘.

예상 결과: 저장 대상이 로컬 연습용인지 확인됩니다.
직접 확인: Firebase MCP와 앱 저장 연결은 다른 것이라고 설명해 봅니다.
막히면: 환경이 없으면 검증된 C2를 사용합니다. localStorage 대체를 Firebase 성공이라고 하지 않습니다.

[X07] 비교 기록 저장 구현
준비: X06 연결 확인 · 현재 비교 자료

그대로 복사할 완성 예시
‘비교 기록 저장’ 버튼을 현재 앱에 추가하고 확인된 로컬 Firestore 에뮬레이터에 연결해줘.
보고서 기록 ID·회사 식별자·기간·첫 값·마지막 값·변화율·단위·출처·조회 시각·저장 시각을 함께 저장해줘.
같은 조회 결과는 같은 ID로 한 번만 저장하고 새 조회 결과는 새 ID로 구분해줘. JSON은 내부 처리야.
저장 중·완료·실패를 구분하고 실제 쓰기 성공 후에만 완료 표시해줘.
저장소에서 같은 ID를 다시 읽어 값이 맞는지 확인해줘.

예상 결과: 완료 표시와 저장소 기록이 일치합니다.
직접 확인: 같은 보고서로 두 번 눌러 중복 기록이 늘지 않는지 봅니다.
막히면: 화면에 카드만 추가해 성공으로 처리하지 않습니다. 실제 쓰기 응답을 확인합니다.

[X08] 새로고침 후 기록 읽기
준비: X07에서 저장한 기록 한 개

그대로 복사할 완성 예시
페이지를 다시 열어도 로컬 Firestore에서 비교 기록 목록을 읽어 표시하게 해줘.
회사명·기간·저장 시각을 보여주고 기록을 누르면 당시 자료로 열어줘. ‘저장 당시 기록’이라고 표시해줘.
빈 목록과 읽기 실패를 구분하고 브라우저 메모리만으로 저장을 흉내 내지 마.
새로고침 후 같은 ID·수치가 보이는지 확인해줘. 에뮬레이터 재시작 후 보존은 별도 설정 없이는 보장하지 마.

예상 결과: 새로고침해도 저장 당시 기록을 읽습니다.
직접 확인: 새로고침 전후 ID와 값 하나를 맞춥니다.
막히면: 브라우저 새로고침과 에뮬레이터 재시작은 다른 시험입니다.

[X09] 리서치 점검 스킬 만들기
준비: 기본 앱·Google 연결이 동작하는 프로젝트

그대로 복사할 완성 예시
현재 프로젝트에 ‘리서치 점검’ 재사용 절차를 만들어줘. 설치된 Antigravity가 읽는 Skills 위치에 기존 설정을 보존하며 추가해줘.
순서는 ①확정한 관심 시트 A1:E3 읽기 ②앱 관심 목록과 비교 ③최근 저장 기록의 출처·조회 시각 확인 ④일치·차이·실패를 표로 보고야.
읽기만 하고 시트·Docs·앱 데이터는 바꾸지 마. 접근 못한 자료는 미확인으로 표시해줘.
실제 파일과 현재 환경에서 쓸 수 있는 호출 방법을 알려줘.

예상 결과: 같은 순서로 점검하는 프로젝트 스킬이 생깁니다.
직접 확인: 규칙은 기준, 스킬은 수행 순서라고 설명해 봅니다.
막히면: 미지원 환경은 TXT 절차를 재사용하고 스킬 등록은 미완료로 표시합니다.

[X10] 점검 수동 실행
준비: X09의 리서치 점검 절차

그대로 복사할 완성 예시
방금 만든 ‘리서치 점검’ 절차를 지금 한 번 실행해줘.
확정한 시트와 앱 관심 목록이 같은지, 최근 기록에 출처·조회 시각이 있는지 읽기만 해서 확인해줘.
대상·확인 시각·결과·이유를 표로 보여줘. 접근 못한 자료는 미확인으로 남겨줘.
수정·문서 추가·외부 발송·예약 등록은 하지 마.

예상 결과: 점검 결과가 같은 형식으로 나옵니다.
직접 확인: 원본을 직접 읽은 근거가 있는지 봅니다.
막히면: 원격 에이전트가 로컬 앱을 못 읽으면 실제 접근 가능한 내보낸 기록만 대상으로 고정합니다.

[X11] 2분 뒤 한 번 예약
준비: X10 수동 성공 · 강사가 현재 환경의 예약 지원 확인

그대로 복사할 완성 예시
/schedule 2분 뒤에 방금 수동 성공한 ‘리서치 점검’을 이 대화에서 한 번만 실행해줘. 접근 가능한 동일 대상만 읽고 결과를 이 대화에 남겨줘. 파일·시트·Docs 수정, 외부 발송, 반복 예약은 하지 마. 이 1회 예약 등록을 승인해. 예약 ID와 예정 시각·시간대를 알려줘.

예상 결과: 예약 ID·대기 상태가 나옵니다. 아직 실행 성공은 아닙니다.
직접 확인: 다른 실습 후 X12에서 확인합니다. 대화와 실행 환경을 유지합니다.
막히면: 예약 미지원이면 수동 점검까지만 기록합니다. 말로 한 약속은 예약 성공이 아닙니다.

[X12] 실제 예약 결과 확인
준비: X11에서 만든 해당 1회 예약

그대로 복사할 완성 예시
이번 수업에서 방금 만든 1회 예약만 확인해줘.
예약 ID·대기/실행/실패 상태·실제 실행 시각·점검 결과를 구분해줘. 결과 없이 시간이 지났다고 성공으로 보지 마.
수업 종료 시 아직 대기 중이면 그 예약 하나만 취소해도 돼. 다른 예약은 건드리지 마. 남은 대기 작업이 없는지 확인해줘.

예상 결과: 등록·실행·자료 점검 결과를 구분할 수 있습니다.
직접 확인: 예약 실행 성공 후에도 자료 읽기는 실패할 수 있습니다.
막히면: 장기 반복 자동화는 등록하지 않습니다. 미실행이면 그대로 적습니다.
