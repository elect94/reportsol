[01] 만들 도구와 완료 기준
준비: 강사가 준비한 시작 프로젝트
이 단계 기본값: 앱: 두 회사 리서치 노트 / AAPL·MSFT / 최근 한 달 / USD

그대로 복사할 완성 예시
‘두 회사 리서치 노트’를 주식 초보자용으로 만들 거야.
기본 대상은 애플 AAPL·마이크로소프트 MSFT, NASDAQ, USD, 최근 한 달 일별 종가야. 이후 비교·보고서·저장·점검까지 이 값을 유지해줘.
‘기본 예제로 시작’을 누르면 두 회사를 선택하고 같은 기간을 불러오게 하자. 검색은 다른 회사를 찾는 기능으로 유지해줘.
검색→기본 예제→비교→Sheets 목록→보고서·Docs→Firestore 기록→1회 점검 흐름의 완료 기준을 적어줘.
기존 파일·class-setup.txt·lesson-defaults.txt를 읽어 요구사항부터 정리해줘. JSON 입력·투자 추천은 넣지 마.

예상 결과: 입력과 확인 방법이 있는 짧은 기준 세 개가 나옵니다.
직접 확인: “AAPL을 검색하면 애플이 나온다”처럼 직접 확인할 동작인지 봅니다.
막히면: 길면 “검색·비교·저장 각각 한 문장으로 줄여줘”라고 요청합니다.

[X01] 프로젝트 규칙 적용
준비: Workspace Rules 또는 확인된 프로젝트 규칙 위치
이 단계 기본값: 규칙: 초보 리서치 도구 / 이 프로젝트만 / 기본값 유지

그대로 복사할 완성 예시
‘두 회사 리서치 노트’ 프로젝트에만 ‘초보 리서치 도구’ 규칙을 추가해줘. 기존 규칙은 보존해줘.
기본값은 AAPL·MSFT, 최근 한 달, USD야. 종목·기간을 매 단계 다시 묻지 말고 사용자가 바꾸기 전까지 유지해줘.
쉬운 한국어·회사명 우선, 수치의 단위·기준 날짜·출처, 실제/가상/실패 구분, 한 기능 수정 후 재확인을 규칙으로 넣어줘.
현재 버전의 Workspace Rules 위치에 저장하고 전역 설정은 바꾸지 마.
설명 예시는 ‘교육용 가상 값 110 USD · 기준일 2026-10-30 · 출처: 계산 연습’으로 보여줘. 실제 회사 가격처럼 표시하지 마.

예상 결과: 프로젝트 규칙과 기준을 지킨 예시 문장이 보입니다.
직접 확인: 다음 가격 화면에서도 기준이 유지되는지 봅니다.
막히면: 메뉴가 다르면 제품 형태를 확인합니다. 기존 AGENTS.md를 덮어쓰지 않습니다.

[02] 먼저 작은 화면 만들기
준비: P01 완료 · 준비된 실행 환경
이 단계 기본값: 첫 선택: 두 회사 / 기본 버튼: 기본 예제로 시작

그대로 복사할 완성 예시
기존 프로젝트에 ‘두 회사 리서치 노트’ 화면을 만들어줘.
첫 화면의 기본 선택은 애플 AAPL·마이크로소프트 MSFT, 기간은 최근 한 달, 단위는 USD야. ‘기본 예제로 시작’ 버튼을 크게 배치해줘.
검색창·가격·비교·관심 목록·보고서·저장 영역을 두고, 아직 연결하지 않은 곳은 ‘실제 조회 미연결’이라고 표시해줘.
로딩·결과 없음·실패를 구분하고 작은 화면·키보드를 지원해줘. 사용자가 JSON을 입력하거나 종목·기간을 새로 고르게 하지 마.
기존 실행 규칙대로 열어 기본 선택 표시와 버튼을 확인해줘.

예상 결과: 첫 화면에 두 회사·최근 한 달·USD가 채워져 있습니다.
직접 확인: 기본 예제로 시작 버튼을 누릅니다. 연결 전에는 미연결 표시가 정상입니다.
막히면: “현재 시작 방법과 오류를 확인해서 이 프로젝트만 실행해줘”라고 요청합니다.

[03] Sheets 연결과 최초 배포
준비: 미배포 상태의 P02 HTML만 준비합니다. 배포 주소는 아직 없습니다.
이 단계 기본값: Sheets: 리서치 연습 - 관심 목록 / 관심종목 / AAPL·MSFT

그대로 복사할 완성 예시
프롬프트 2까지 만든 HTML은 아직 미배포 상태야. 배포 주소를 요구하지 말고 Sheets 연결 코드와 최초 배포를 준비해 줘.
원본을 보존하고 apps-script/Index.html과 Code.gs를 만들어 줘. Apps Script 웹앱에서 google.script.run으로 호출하고 doGet은 Index를 열어 줘.
setupLesson은 ‘리서치 연습 - 관심 목록’ 시트를 최초 한 번 생성해 ID를 보관해 줘. 관심종목 탭의 열은 회사명·종목코드·시장·메모·사용. 기본 행은 애플/AAPL/NASDAQ/아이폰 회사/예, 마이크로소프트/MSFT/NASDAQ/윈도 회사/예야.
기존 btn-export-sheets를 ‘Sheets에 관심 목록 저장’으로 연결해 줘. 같은 종목은 중복 없이 갱신하고 성공 응답에만 표 링크를 보여 줘. 표를 다시 읽는 버튼도 추가해 줘.
기존 비교·보고서와 가상 표시는 유지해 줘. 배포 전 로컬 미리 보기에서는 외부 연결 대기를 표시해 줘. 파일 2개 복사 → setupLesson 실행 → 나만 접근하는 웹앱 최초 배포 → 발급된 주소에서 Sheets 저장 확인 순서로 안내해 줘. 배포는 내가 직접 할게. 코드 생성만으로 배포나 연결 성공이라고 하지 마.

예상 결과: 코드 준비 후 직접 최초 배포하고, 발급된 주소에서 Sheets 저장을 확인합니다.
직접 확인: 시트의 AAPL 메모를 아이폰 회사 → 메모 수정 확인으로 바꾸고 앱에서 다시 읽습니다. 두 번 저장해도 두 행인지 봅니다.
막히면: google.script.run 오류면 로컬 파일이 아니라 Apps Script의 배포 URL인지 먼저 확인합니다.

[04] Docs 연결
준비: P03에서 최초 배포와 Sheets 저장을 확인한 뒤 같은 파일·주소를 사용합니다.
이 단계 기본값: Docs: 리서치 연습 - 비교 기록 / 기존 보고서 버튼 사용

그대로 복사할 완성 예시
Sheets가 연결된 apps-script/Index.html과 Code.gs에 Google Docs 저장만 추가해 줘.
btn-create-report는 현재 sampleData로 수치·변화율·기간·출처를 계산해 미리 보기를 만들어 줘. 남아 있는 110 USD와 20거래일 고정 문구를 실제 배열의 값·기간·8개 관측치로 바로잡아 줘. ‘교육용 가상’과 ‘실제 시세 미연결’을 화면·보고서에 유지해 줘. 기본 예제 시작 전에는 작성을 막아 줘.
btn-export-docs는 ‘Docs에 보고서 저장’으로 연결해 줘. google.script.run과 DocumentApp으로 ‘리서치 연습 - 비교 기록’ 문서를 최초 한 번 만들고 ID를 보관해 줘. 대상·수치·관측 기간·가상 출처·미확인을 미리 보기와 같게 저장해 줘.
한 보고서에는 같은 ID를 유지하고 재클릭해도 중복 추가하지 마. 저장 중에는 버튼을 잠그고 완료 응답에서 실제 문서 링크를 보여 줘. 실패하면 성공 표시를 하지 마.
Sheets 기능은 유지해 줘. 바뀐 파일 전체와 권한 재확인·기존 배포의 새 버전 적용 순서를 알려 줘. 적용은 내가 직접 할게.

예상 결과: 앱의 보고서와 같은 내용이 본인 Google Docs에 저장됩니다.
직접 확인: 문서 링크를 열어 237.50 USD·433.00 USD·교육용 가상·2026-11-06을 대조하고 재클릭 시 중복이 없는지 봅니다.
막히면: 권한이 늘어난 경우 본인 스크립트의 요청 범위를 확인합니다. 배포 관리에서 새 버전을 적용했는지 확인합니다.

[05] Firebase 연결
준비: Firebase 콘솔에서 웹 앱 등록·익명 로그인·Firestore 규칙까지 준비합니다.
이 단계 기본값: 표시 이름: 리서치 연습 / 웹 앱: research-note / 사용자별 comparison_records

그대로 복사할 완성 예시
Sheets·Docs가 연결된 기존 앱에 Firebase 저장과 다시 읽기만 추가해 줘.
내가 제공한 Firebase 웹 앱 설정을 사용해 줘. 설정이 없으면 콘솔의 firebaseConfig만 요청하고 프로젝트 ID를 만들지 마. 서비스 계정 비밀키는 사용하지 마.
Web SDK와 익명 로그인을 사용하고 인증 상태 복원 후 users/{uid}/comparison_records/{reportId}에 현재 보고서 ID·두 회사 값·가상 표시·관측 기간·본문·서버 저장 시각을 저장해 줘. 사용자 본인 경로만 허용하는 firestore.rules도 만들어 줘.
btn-save-firestore는 ‘Firebase에 기록 저장’으로 연결하고 보고서 작성 전에는 막아 줘. 같은 ID는 갱신하고 서버 재조회 성공 뒤에만 저장 완료로 표시해 줘.
‘최근 기록 다시 읽기’ 버튼으로 서버에서 최근 5개를 읽어 화면에 보여 줘. 같은 브라우저 새로고침 후 동일 사용자 ID와 기록을 확인해 줘. 오프라인 캐시를 서버 조회 성공으로 표시하지 마.
기존 Google 버튼과 화면을 유지해 줘. 설정·인증·권한 오류를 나눠 안내하고 Apps Script 새 버전 적용 방법과 실제 미검증 항목을 알려 줘.

예상 결과: 같은 브라우저에서 새로고침해도 Firebase의 본인 기록을 다시 읽습니다.
직접 확인: Firestore 콘솔의 실제 문서·앱 재조회 값·보고서 ID를 대조합니다. 다른 사용자 경로는 규칙 테스트에서 거부되어야 합니다.
막히면: permission-denied는 로그인 UID·문서 경로·규칙을 대조합니다. 브라우저 저장 제한이면 UID 유지 여부부터 확인합니다. allow true로 열지 않습니다.
